# 21 點

入口：功能導覽 → 21 點，路徑 `/blackjack`。
只有已登入的網站成員可操作。下注使用星之碎片，不提供現金兌換功能。

## 固定規則

- 一名玩家對系統莊家。美式暗牌及預先檢查 Blackjack。
- 莊家 soft 17 停牌；玩家普通勝局含本金領回 2 倍、平手領回本金。
- 原始兩張 Blackjack 賠 3:2，含本金領回 2.5 倍。雙方 Blackjack 平手。
- A 明牌先決定保險再檢查暗牌。保險為原始下注一半，莊家 Blackjack 時含保險本金領回 3 倍保險金。
- 前兩張可加倍，僅補一張。相同點數可分牌，最多 4 手，分牌後可加倍。
- 分 A 各只補一張，不可再分 A；分牌後 21 點不是 Blackjack。
- 不提供投降、五張牌自動獲勝；最低 2 點且下注只能是正偶數。保險、加倍、分牌都另扣款，餘額不足不可操作。

## 共用牌堆及資料表

`blackjack_shoe` 保存全站共用的 5 副標準牌（260 張、每個牌面各 5 張）、UUID、抽牌位置及建立時間。
使用系統安全亂數洗牌，依固定順序消耗到第 260 張才建立下一套。
若在牌局中途用完，下一張來自新洗的 260 張；新套與尚未完成的舊套牌局可同時存在。
`blackjack_round` 保存會員自己的牌局、手牌、莊家暗牌、版本與結算，每位會員同時只能有一局未完成。
`blackjack_request` 保存 UUID 操作識別碼及操作指紋，避免重試重複下注或發牌。
這些資料表僅由後端寫入；含未發牌順序與莊家暗牌的資料僅應由受信任維運者查閱。

每個操作均在 SQLite `BEGIN IMMEDIATE` 交易內處理，發牌位置、牌局、操作收據、帳本一起提交或回滾。
結算與扣款使用 `star_shard.transactionType = blackjack`，`transactionSource` 為該局 UUID。
遊戲 API 不傳回莊家暗牌、未發牌顺序或其他玩家資訊。已下注的牌局不因登出、換頁、重啟而取消，重新登入可繼續。
瀏覽器保留不確定操作的 UUID；網路中斷時請按「重試操作」，不要用新的識別碼重建操作。

## 相依套件與部署

固定使用 [blackjack-api 1.1.0](https://pypi.org/project/blackjack-api/) 的 Deck、Card、Hand 做牌組構成、A 點數及分牌判斷。
上游模擬器的完整遊戲迴圈不支援本專案的美式 peek 時序與全站持久化牌堆，因此沒有使用其 BlackJack 類別結算。
本專案另以明確狀態機實作上述規則、整数賠付與帳本交易，並以固定牌序測試。
安裝更新後的 `backend/requirements.txt` 並重建後端／前端映像檔；資料表在第一次遊戲請求時建立。
撲克牌使用既有 `frontend/src/assets/poker.webp`，不使用圖集中的鬼牌。
